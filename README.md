# TrueTone

Voice-first feedback collection with real-time AI analysis.

**Speak -> Transcribe -> Analyse -> Dashboard**

---

## Architecture

```
Browser
  |
  +-- MediaRecorder API --> Cloudinary (signed upload -- audio never hits the server)
  |
  +-- POST /api/responses (metadata only)
          |
          v
    Express API  -->  Neon PostgreSQL (Prisma ORM)
          |
          v
    pg-boss Queue (uses same Postgres connection -- no Redis)
          |
          v
    Background Worker
          +-- Sarvam AI  -->  Transcript (Hindi + English)
          +-- OpenRouter (Mistral Small 24B)  -->  Sentiment + Urgency + Themes
                  |
                  v
            DB Update  -->  WebSocket notify  -->  Live dashboard update
```

---

## Key Technical Decisions

### pg-boss over Redis/BullMQ

The job queue runs on the same Postgres instance as the rest of the app. This eliminates a second managed service, keeps the free-tier deployment viable, and gives atomic job claiming through Postgres transactions -- no distributed lock needed.

### Signed Cloudinary Uploads

Audio goes directly from the browser to Cloudinary using a short-lived signed URL generated by the server. The raw audio bytes never pass through the API server, removing a major attack surface and avoiding bandwidth costs.

### Multi-Key API Rotation (Sarvam AI)

Sarvam's free tier rate-limits aggressively. The worker accepts a comma-separated list of API keys via env var and rotates through them round-robin, with automatic failover on 429/403 responses. This makes the free tier usable in a demo without paying for a higher plan.

### Atomic Job Claiming

```sql
UPDATE responses
SET status = 'PROCESSING', workerId = $1
WHERE id = $2 AND status = 'PENDING'
```

`updateMany` with a status pre-condition prevents two worker instances from claiming the same job, without needing a distributed lock or a Redis SETNX.

### SSRF Protection

The worker downloads audio from Cloudinary for the STT step. The download URL is validated against an allowlist (`res.cloudinary.com` only) before the HTTP request is made, preventing an attacker from using the worker as a proxy to hit internal services.

### Multi-Tenant from Day One

Every DB query is scoped to `orgId`. There are no admin queries that bypass org isolation. This was a deliberate schema decision, not a retrofit.

### Real-Time Processing via WebSocket

When a voice response is submitted, the browser opens a WebSocket connection to `/ws/response/:responseId`. The background worker emits status transitions (`processing` -> `transcribing` -> `analyzing` -> `done`) through the WebSocket hub. The dashboard and public survey page both update live without polling or page refresh.

## Stack

| Layer | Tech |
|---|---|
| Frontend | React 19, Vite, TypeScript, Tailwind v4, shadcn/ui, Recharts, WaveSurfer.js |
| Backend | Express.js, TypeScript, Zod, ws (WebSocket) |
| Database | PostgreSQL (Neon) via Prisma ORM |
| Queue | pg-boss |
| Storage | Cloudinary (signed upload) |
| AI | Sarvam AI (STT) + OpenRouter / Mistral Small 24B (LLM) |
| Deploy | Vercel (frontend) + Render (backend) + Neon (DB) |

## Running Locally

```bash
# 1. Install dependencies
cd client && npm install
cd ../server && npm install

# 2. Set environment variables
cp .env.example .env
# Fill in: DATABASE_URL, CLOUDINARY_*, SARVAM_API, OPEN_ROUTER_API, JWT_SECRET

# 3. Push DB schema
cd server && npx prisma db push

# 4. Start everything
npm run dev        # server (port 3000)
cd ../client && npm run dev   # client (port 5173)
```
